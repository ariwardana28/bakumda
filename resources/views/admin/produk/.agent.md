# 🤖 Agent Instructions - Produk Admin Views

**Context**: Ini adalah folder yang berisi views untuk manajemen produk di admin panel. Styling dan struktur sudah distandarisasi dan HARUS dipertahankan.

---

## 📖 Understanding the Current State

### File Structure
```
resources/views/admin/produk/
├── index.blade.php      (List view dengan search & pagination)
├── create.blade.php     (Form untuk create produk)
├── edit.blade.php       (Form untuk edit produk)
├── .instructions.md     (Style guidelines)
└── .prompt.md          (Prompt untuk consistency)
```

### Key Characteristics
- **Design System**: Tailwind CSS dengan custom color scheme
- **Primary Color**: blue (#f97316 / bg-blue-600)
- **Theme**: Light mode only (no dark mode)
- **Icons**: Heroicons SVG inline
- **Pattern**: Follows pelatihan views structure
- **Permissions**: Uses Laravel @can directives

---

## 🎯 Core Principles

### 1. **Color Consistency**
```
blue-600 = Primary actions, highlights, focus states
blue-50  = Icon backgrounds, light backgrounds
Sky-600    = View/Detail actions
Amber-600  = Edit actions  
Red-600    = Delete actions
Emerald-600= Success/Available status
Gray-*     = Neutral backgrounds and text
```

### 2. **Layout Pattern**
```
Every page follows this structure:
1. Header Section (title + description + action button)
2. Session Alerts (if any)
3. Main Card Container
   - Card Header (with icon, title, subtitle, search)
   - Content Area (table/form/gallery)
   - Footer (pagination if needed)
```

### 3. **Component Reusability**
- Buttons: Always use predefined classes
- Inputs: Always use standard input pattern with labels
- Cards: Always use `rounded-2xl shadow-sm border-gray-100`
- Icons: Always inline SVG from Heroicons

## ⚠️ When You See a Modification Request

### Check These Questions First:
1. ❓ Is the request about styling/colors? 
   → Refer to `.instructions.md`
2. ❓ Is the request about adding new fields?
   → Maintain existing pattern
3. ❓ Is the request about changing structure?
   → Consult team, don't just change
4. ❓ Is the request about fixing a bug?
   → Fix bug, preserve styling

### Before You Edit:
- [ ] Read current file content completely
- [ ] Identify which file(s) need changes
- [ ] Check if changes should apply to all 3 files
- [ ] Verify styling matches guidelines
- [ ] Check for responsive design
- [ ] Confirm permission checks are in place
- [ ] Review error message styling

### While You Edit:
- [ ] Maintain line-by-line consistency
- [ ] Use `multi_replace_string_in_file` for multiple changes
- [ ] Keep class names exactly as specified
- [ ] Don't shorten or abbreviate styling
- [ ] Preserve all comments and structure
- [ ] Test mentally: Does it match the pattern?

### After You Edit:
- [ ] Verify all 3 files are consistent (if applicable)
- [ ] Check that colors are correct
- [ ] Ensure responsive classes are present
- [ ] Confirm permissions are checked
- [ ] Look for any dark mode classes (shouldn't be any)

## 🔄 Common Scenarios & How to Handle

### Scenario 1: Add a New Field to Create Form
```
✅ DO:
1. Add inside appropriate section (e.g., "Informasi Dasar")
2. Use standard label + input pattern
3. Add error handling
4. Keep spacing consistent
5. Add to edit form too if needed

❌ DON'T:
1. Change existing field styling
2. Use different pattern than others
3. Forget @error directive
4. Skip responsive design
```

### Scenario 2: Change Button Color
```
✅ DO:
1. Update .instructions.md with new color
2. Change in all 3 files consistently
3. Update .prompt.md with new rule
4. Test hover states
5. Notify team about change

❌ DON'T:
1. Change only one button
2. Use arbitrary colors
3. Forget hover states
4. Skip error/disabled states
```

### Scenario 3: Add New Status Type
```
✅ DO:
1. Define new color in .instructions.md
2. Add logic to index.blade.php status section
3. Add select option in create.blade.php
4. Add select option in edit.blade.php
5. Test badge color display

❌ DON'T:
1. Use undefined colors
2. Add status only to one file
3. Forget to add to select options
4. Skip documentation
```

### Scenario 4: Fix Layout Issue on Mobile
```
✅ DO:
1. Check current responsive classes
2. Test layout on sm/md/lg breakpoints
3. Adjust grid columns or widths
4. Verify all files have same fix
5. Update .instructions.md if pattern changes

❌ DON'T:
1. Add arbitrary breakpoints
2. Hide elements without reason
3. Break desktop layout
4. Skip other files
```

## 📐 Exact Styling Patterns to Follow

### Button Pattern
```blade
<!-- Primary (blue) -->
<button class="bg-blue-600 hover:bg-blue-700 text-white font-bold py-2.5 px-5 rounded-xl shadow-lg shadow-blue-200 transition duration-300">
  Action
</button>

<!-- Secondary (Gray) -->
<a class="bg-gray-100 hover:bg-gray-200 text-gray-700 font-semibold px-4 py-2.5 rounded-xl transition">
  Secondary
</a>

<!-- Icon Action -->
<a class="p-2 bg-sky-50 text-sky-600 hover:bg-sky-100 rounded-lg transition">
  <svg>...</svg>
</a>
```

### Input Pattern
```blade
<div>
  <label class="block text-xs font-semibold text-gray-600 uppercase tracking-wider mb-2">
    Label Text <span class="text-red-500">*</span>
  </label>
  <input 
    type="text" 
    name="field" 
    class="w-full px-4 py-2.5 bg-gray-50 border border-gray-200 rounded-xl text-sm focus:bg-white focus:ring-2 focus:ring-blue-500 focus:border-transparent transition duration-200 outline-none @error('field') border-red-500 bg-red-50/50 @enderror">
  @error('field') 
    <p class="text-red-500 text-xs mt-1.5">{{ $message }}</p> 
  @enderror
</div>
```

### Card Pattern
```blade
<div class="bg-white rounded-2xl shadow-sm border border-gray-100 overflow-hidden">
  <div class="p-6 md:p-8 border-b border-gray-100 flex items-center gap-3">
    <div class="p-2 bg-blue-50 rounded-xl text-blue-600">
      <!-- Icon -->
    </div>
    <div>
      <h3 class="text-lg font-bold text-gray-800">Title</h3>
      <p class="text-xs text-gray-400">Subtitle</p>
    </div>
  </div>
  <!-- Content -->
</div>
```

## 🚫 Absolute Constraints

These MUST NOT be changed without explicit approval:

1. ❌ Primary color (blue #f97316)
2. ❌ Layout structure (header → card → content → footer)
3. ❌ Button styling patterns
4. ❌ Input field styling
5. ❌ Card styling (`rounded-2xl shadow-sm border-gray-100`)
6. ❌ Icon styling (Heroicons 24px)
7. ❌ Permission checks (@can directives)
8. ❌ Responsive breakpoints (mobile first, md breakpoint)
9. ❌ Typography rules (sizes, weights, tracking)
10. ❌ Spacing conventions (p-6 md:p-8, gap-4, etc)
